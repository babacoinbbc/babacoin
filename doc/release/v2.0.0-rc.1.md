# Babacoin Core V2.0.0 — Release Candidate 1

V2 brings a redesigned day/night wallet, safer database/backup handling and a
larger validation matrix to the existing BBC blockchain.

**Release candidate:** validate in isolated data directories first. This is not
an automatic mainnet rollout or a guarantee of compatibility with every
historical node. Read `MIGRATION.md` and `PLATFORM-SUPPORT.md` before production
use. Existing V1 and earlier V2 test assets are preserved.

## Included improvements

- Persistent day/night themes, navigation, balance summary and bounded recent
  activity bars, with font scaling and Turkish/English localization support.
- Original project-supplied gold branding, with a larger coin and a legible
  stacked wordmark rendered for high-DPI sidebars without redrawing the artwork.
- Windows CRLF stylesheet normalization and correct filtering of multiple
  platform sections; the actual theme loader has a regression test. The initial
  packaged-Windows visual check caught this issue despite passing unit suites.
- Earlier splash feedback and less startup font enumeration; a reproduced
  pixel-sized-font abort has a regression test. Verification/rescans stay on.
- An incomplete startup rescan now fails closed before advancing the persisted
  checkpoint; an integration regression checks abort, retained locator and retry.
- Correct disk-index decoding, BDB 4.8.30 portability checks, safe backup failure
  behavior, accurate DKG sender attribution and strict test completion checks.
- Ubuntu LTS 18.04–26.04 x86_64/ARM64 and Debian 12/13 x86_64/ARM64 packages.
- Native Windows x64, macOS Intel and Apple Silicon build/test paths.
- Windows 11 ARM64-host testing of the x64 package under emulation; no native
  Windows ARM64 executable is claimed.
- Fresh regtest preview launchers and verified Linux download-only installation.
- Opt-in HTTPS Explorer peer discovery in the desktop Network settings, with
  strict public-address filtering, response limits and ordinary peer validation.
- Smartnode registration wizard with collateral/readiness checks, public BLS key
  input, signed local preparation, funding guards and explicit broadcast consent.
- A Web Wallet tab that opens the official website in the default browser;
  embedded browsing is deferred, and no wallet import or key sharing is automatic.
- Legacy quick-setup RPC credentials now use the core cryptographic RNG and
  configuration-safe characters. Recovery configuration export is exclusive,
  checked and committed before attempting registration broadcast.
  Legacy scripts that could modify OS security or interrupt package managers
  are retired; no automatic production upgrade replaces them.
- English README, platform coverage, settings, migration, goals and dependency
  source/license notices.

## Package integrity and test gate

Every required platform job must succeed before this release can be assembled.
The gate includes core, Qt, utility, RPCAuth, secp256k1, UniValue, source guards,
archive-safety checks and isolated wallet smoke tests. Download `SHA256SUMS`
and `RELEASE-MANIFEST.json`; they identify the source and executable hashes.
A matching checksum verifies integrity, not a formal security certification.

Extract into a new folder. For visual QA run `TEST-WALLET.cmd` on Windows or
`bash TEST-WALLET.sh` on Linux/Mac. These launchers use new regtest data and GUI
preferences with external P2P disabled. Never copy a real wallet into that folder.
Direct application launch can use an existing production data directory.

Mac GUI applications are bundled and ad hoc signed, not Apple notarized.
No Microsoft publisher certificate is claimed. Mac CLI tools retain documented
Homebrew dependencies. Linux packages require matching distro runtime libraries.
Raspberry Pi OS 64-bit is a Debian ARM64 compatibility target; physical Pi
hardware/display tests remain separate. Additional OS/32-bit/mobile targets are
roadmap items, not advertised as shipped support.

## Network and wallet boundaries

The audited mainnet genesis, ports, address prefixes, PoW, monetary rules and
collateral/founder schedules are retained. Existing main-branch differences
from V1 include the 1,250,000 collateral/founder destination schedules and the
immediate spork-key rotation. This candidate adds no new activation and does
not move collateral or broadcast governance/spork changes.

Prior audit validation included fresh encrypted/unencrypted V1 wallet round
trips, restore/signature tests, localhost P2P and bounded historical block/UTXO
comparisons. It did not certify a complete chain replay, every production wallet
or network-wide adoption. A slow real-wallet startup must be diagnosed from its
own loading/rescan phases; UI work is not a claim that a required scan vanishes.

The protected main branch's independent-review requirement is retained. Passing
CI and publishing this candidate do not replace that review or an operator's
production migration assessment.
