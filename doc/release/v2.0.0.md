# Babacoin Core V2.0.0 — Superseded unpublished draft

This draft was held before publication after GUI synchronization waits were
reported. Use V2.0.1; the text below records the superseded release plan.

Release Git tag: `v2.0.0-mainnet`. Application/package version: `2.0.0`.
The older April `v2.0.0` Git tag remains a historical source reference.
`RELEASE-MANIFEST.json` identifies the exact compiled source and distribution tag.

V2.0.0 is the final release build of the redesigned Babacoin mainnet wallet.
The compiled release flag is enabled. The old RC4 prerelease banner is absent;
real synchronization, network and wallet warnings remain enabled. Changing a
GitHub release label alone cannot change a previously installed RC executable.
Install the V2.0.0 package to replace an RC build.

## Download and install

Windows users should choose `babacoin-v2.0.0-windows-x86_64-setup.exe`.
The guided per-user installer includes the matching DLLs and Qt plugins, checks
for running wallets, can retain an existing data directory and preserves wallet
data on reinstall/uninstall. Back up the wallet and close Babacoin before Setup.
Portable users must retain the complete extracted folder, including its DLLs.

Packages cover Ubuntu LTS 18.04–26.04 and Debian 12/13 on x86_64/ARM64,
macOS Intel/Apple Silicon, and Windows x64. Windows ARM64 runs the tested x64
package through emulation. Raspberry Pi OS 64-bit is a Debian ARM64 compatibility
target; physical Raspberry Pi validation is still pending. Choose the archive
matching the distribution and architecture, not merely any Linux archive.

Verify `SHA256SUMS`, `RELEASE-MANIFEST.json`, `INSTALLER-MANIFEST.json` and
`INSTALLER-TESTS.json`. Mac GUI bundles use ad hoc signatures and are not Apple
notarized. No Microsoft publisher certificate is claimed. Read
`PLATFORM-SUPPORT.md` for runtime dependencies and support limits.

## Wallet improvements

- Gold/teal day and night themes, clearer balances and transaction rows,
  localized thousands/decimal separators and high-DPI branding.
- A responsive startup view, actual wallet-rescan percentages, elapsed time,
  safe cancellation, and live connection/validated-height/synchronization cards.
- Batched history loading and more responsive handling of large wallets.
- Optional HTTPS Explorer peer discovery under Settings → Options → Network.
  Proxy and explicit network restrictions remain respected.
- Guided Smartnode preparation and an external-browser Web Wallet tab.
  Neither installs, registers nor transfers collateral automatically.
- Full and incremental public-block bootstrap ZIPs with a separate manifest,
  checksums and English import instructions. Normal consensus validation runs.

The tested application base is RC4; this release enables the final build flag,
adds a publication guard against a stable tag/RC binary mismatch, and adds
bootstrap tooling/docs. It does not introduce another consensus transition or
change key serialization, balances, block rewards or mainnet identity.

## Mandatory coordinated network upgrade

All validating wallets, exchanges, pools and nodes must upgrade **before the
first 2,000,000 BBC Smartnode registration**. Early registration has no opening
block. Unmodified V1 can reject the first such registration block; retaining
V1 as a historical download does not make it compatible with the new rule.

The 1,800,000 BBC tier stops qualifying for rewards at block **1,250,000**.
Installing V2 does not automatically move collateral, register a Smartnode,
submit a spork or upgrade other network participants. Read `NETWORK-UPGRADE.md`
and coordinate operators before using the new rule.

## Validation and recovery

Release assembly requires the complete same-source platform matrix to pass,
including core and Qt tests. The Windows installer is additionally tested on
x64 and ARM64 hosts for installation, startup, reinstall and uninstall with
wallet-preservation fixtures. Runtime smoke tests reject a final-source binary
that still reports the prerelease warning. Manifests identify the exact commits,
binary hashes, platform results and installer payload rather than relabeling RC
executables as final binaries.

Bootstrap structural/Merkle verification and a 1,000-block consensus-import
sample do not constitute an independent full-chain replay. Every importing node
still validates the complete imported chain. Existing wallet-data problems
require diagnosis and backups; installing a newer executable alone does not
repair every historical wallet record. Do not delete `wallet.dat` to resolve a
warning. Read `MIGRATION.md` and retain a verified backup.

This release is not a claim that software is defect-free, that every historical
wallet has been tested, or that network-wide adoption has already happened.
